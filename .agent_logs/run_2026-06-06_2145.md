What you discovered.

I discovered a logic bug involving undocumented complex logic in the backend database query when a user mentions an agent in the chat. The query strictly filtered agents by `Agent.workspace_id == ws_uuid`. Because globally pooled agents have a `workspace_id` of `None`, they were incorrectly excluded from the search results, meaning they would never intercept or respond to chat mentions.

What you fixed/added.

I updated the SQLModel agent query inside `chat_message` in `backend/app/main.py`. The `.where` clause now correctly uses an OR condition (`.where((Agent.workspace_id == ws_uuid) | col(Agent.workspace_id).is_(None))`), allowing agents from the global pool to be matched and respond to user mentions correctly.
