What you discovered.
During the scout phase, I scanned the repository using Pyright to identify missing type hints. I discovered 16 type-checking errors in the backend test files (`tests/test_auth.py`, `tests/test_main.py`, and `tests/test_socket.py`). These errors stemmed from implicitly nullable environment variable returns (`os.getenv`), potentially null database objects before property access (`user.id`), and intentional type mismatches for negative testing (`'not a dict'` passed to a dict-typed parameter).

What you fixed/added.
I fixed the Pyright errors across the test files:
- In `tests/test_auth.py`, added `assert secret_key is not None` before decoding tokens with `jwt.decode` to satisfy the strict string requirements.
- In `tests/test_main.py`, explicitly converted the `os.getenv("EXTENSION_API_KEY")` call to a `str` when constructing header dicts. I also added explicit assertions `assert user is not None` before accessing `user.id` in mocked database operations across the proxy and sync endpoints.
- In `tests/test_socket.py`, I added `# type: ignore` comments to the specific lines where I intentionally pass the string literal `'not a dict'` to the `join_workspace` and `chat_message` parameters to test data validation functions, suppressing the false-positive Pyright alerts.
