What you discovered.
I discovered that the `call_provider_api` function in `backend/app/main.py` was making HTTP POST requests to external AI providers using `httpx.AsyncClient`, but it was not raising exceptions when the responses had HTTP error statuses (like 4xx or 5xx). This means if an API request failed, the application would silently process the error payload (e.g., HTML or JSON error messages) as if it were a successful response from the AI and relay it back to the user.

What you fixed/added.
I added `res.raise_for_status()` after the `await client.post(...)` calls for all three AI providers (OpenAI, Claude, and Gemini) in the `call_provider_api` function. This ensures that any HTTP errors are properly raised as `httpx.HTTPStatusError` exceptions, which can be caught and handled correctly by the calling code, rather than being parsed and returned as successful text. I also added a unit test to verify this behavior.

Next Recommended Target
I recommend looking into adding more robust input validation and handling for the different provider endpoints in the `call_provider_api` function, such as handling malformed provider names before making network requests, or verifying the token structures to fail fast before trying to proxy the AI call.
