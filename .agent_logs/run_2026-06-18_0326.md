What you discovered:
The Python `bcrypt` module has a limitation where it throws a `ValueError` if the input password exceeds 72 bytes. The Pydantic models for `UserCreate` (used for registration) and `LoginRequest` (used for login) in `backend/app/main.py` allowed passwords up to 128 characters (`max_length=128`), creating an unhandled error vulnerability that could lead to a potential Denial-of-Service (DoS) if a user submitted a password longer than 72 bytes.

What you fixed/added:
Modified the `max_length` parameter for the `password` field in both `UserCreate` and `LoginRequest` Pydantic models from 128 to 72 in `backend/app/main.py`. This ensures that FastAPI will automatically reject requests with oversized passwords at the validation layer before they reach the `bcrypt` hashing function, preventing the unhandled `ValueError`.

Another area is missing type annotations for properties of Socket.io event arguments.
