### What you discovered
The frontend application's `fetchData` function in `frontend/src/app/page.tsx` assumed that the `/workspaces` and `/agents` endpoints would always return valid arrays. If the backend returned an error (such as a 401 Unauthorized or a 500 error), the `res.json()` call would resolve to a JSON object (like `{ "detail": "Not authenticated" }`), causing the app to crash entirely when it attempted to iterate over the objects using `Array.prototype.map()`.

### What you fixed/added
Modified the `fetchData` function in `frontend/src/app/page.tsx` to properly validate the fetch responses:
1. Added a check for `!wsRes.ok` and `!agentRes.ok` to throw a catchable error for non-200 responses.
2. Implemented `Array.isArray()` validation to gracefully default to empty arrays if the parsed JSON data is not an array, preventing unhandled `.map()` crashes.
