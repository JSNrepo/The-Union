### What you discovered
During the Scout phase, I discovered an unhandled error condition in the backend `/register` endpoint. Specifically, there is a race condition where if two concurrent requests attempt to register a user with the same username simultaneously, they may both pass the initial check `session.exec(select(User).where(User.username == user.username)).first()`. However, only one will successfully insert into the database. The second one will fail during `session.commit()` with a `sqlalchemy.exc.IntegrityError` due to the unique constraint on the username. Because this error was not caught, the application would crash and return an unhandled 500 Internal Server Error back to the client instead of gracefully handling the conflict.

### What you fixed/added
I modified `backend/app/main.py` to wrap `session.commit()` inside a `try...except` block in the `register` function. If an `IntegrityError` is caught, I call `session.rollback()` and raise a `HTTPException` with a 400 status code and detail "Username already registered". This properly handles the race condition without breaking existing tests, returning a clean 400 error as originally intended for duplicates.
