What you discovered.
In `backend/app/auth.py`, the `get_current_user` dependency parsed the JWT `sub` claim into a `uuid.UUID` using a `try...except ValueError` block. However, if the payload `sub` claim contained non-string types that managed to bypass earlier validation, `uuid.UUID()` would raise an unhandled `TypeError` or `AttributeError` (e.g. `AttributeError: 'int' object has no attribute 'replace'`), which could result in a 500 Internal Server Error instead of the expected 401 Unauthorized exception.

What you fixed/added.
Updated the exception handling around `uuid.UUID(user_id)` in `get_current_user` (`backend/app/auth.py`) to catch `(ValueError, TypeError, AttributeError)` instead of just `ValueError`. This ensures robust exception handling and returns a clean 401 Unauthorized error for any malformed or improperly typed `sub` claims, preventing unhandled 500 errors.
