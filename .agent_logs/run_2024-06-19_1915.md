## Phase 3 Log

**What was discovered:**
During the exploration phase, I discovered an unhandled `cryptography.fernet.InvalidToken` exception in `backend/app/encryption.py` inside the `decrypt_token` function. If the database stores a corrupted token or if the `UNION_MASTER_KEY` changes, `fernet.decrypt` throws this `InvalidToken` exception. This exception was unhandled, causing the `proxy_request` endpoint to return a generic 500 error, and more importantly, causing the `chat_message` Socket.IO event handler to completely crash its worker thread via `asyncio.to_thread()`, resulting in silent failures for connected users.

**What was fixed:**
1. Modified `backend/app/encryption.py` to explicitly catch `cryptography.fernet.InvalidToken` and raise a standard `ValueError("Invalid encryption token")`.
2. Modified `fetch_agent_infos` in `backend/app/main.py` (which powers the WebSocket agent tagging feature) to catch this `ValueError`. When caught, it gracefully treats the agent as offline (`offline: True`) instead of crashing the thread.
3. Modified `fetch_agent_data` in `backend/app/main.py` (which powers the `/proxy-request` endpoint) to catch this `ValueError` and explicitly raise an `HTTPException(status_code=400)` with a clear error message instead of an unhandled 500 Internal Server Error.

**Next Recommended Target:**
Investigate adding robust end-to-end tests for the Socket.IO event handlers and React frontend integration, as currently, tests only exist for the HTTP backend and isolated utility functions, leaving core chat interactivity largely untested.
