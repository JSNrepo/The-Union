What you discovered.
During exploration of the codebase, I discovered that the `SECRET_KEY` assignment in `backend/app/auth.py` was loaded from the environment variable via `os.getenv("SECRET_KEY")`, which caused Pyright to infer its type as `str | None`. This generated missing type hints and assignment errors when the variable was passed to JWT encoding/decoding functions that require exactly a string. I also found that no other tasks out of the five options given by the prompt had severe issues since the test coverage and exception handling across `auth.py`, `encryption.py`, and `main.py` had already been largely optimized to 100%. Therefore, fixing Pyright errors and missing type hints constituted the only relevant problem.

What you fixed/added.
I fixed the Pyright error and added correct type hints to `backend/app/auth.py` by capturing the environment variable return value into `_SECRET_KEY` and setting `SECRET_KEY: str = _SECRET_KEY` after ensuring it is not null, which formally guarantees to Pyright that `SECRET_KEY` is a string. This eliminates the Pyright error for both `jwt.encode` and `jwt.decode`.
