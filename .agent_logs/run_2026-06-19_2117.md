What you discovered.
During Phase 1 (Scout), I analyzed the backend test coverage and discovered missing test coverage for `ValueError` exceptions raised during session token decryption. Specifically, when `cryptography.fernet.InvalidToken` is caught in `decrypt_token()` (in `backend/app/encryption.py`), it raises a `ValueError`. This exception was handled in `proxy_request` and `chat_message` (in `backend/app/main.py`), but the error handling paths were never executed by the test suite, leaving their behavior unverified.

What you fixed/added.
During Phase 2 (Execute), I added the missing test cases to achieve 100% test coverage for the token decryption error handling:
1.  **`backend/tests/test_encryption.py`**: Added `test_decrypt_invalid_token` to verify that `decrypt_token()` correctly raises a `ValueError` for an invalid token format.
2.  **`backend/tests/test_main.py`**: Added `test_proxy_request_invalid_token` to ensure the `/proxy-request` endpoint returns a `400 Bad Request` with a descriptive message when an agent's stored session token is corrupt or invalid.
3.  **`backend/tests/test_socket.py`**: Added `test_chat_message_mention_agent_invalid_token` to verify that the WebSocket chat listener handles invalid tokens smoothly without throwing server errors, instead notifying the chat room that the specific AI agent is offline.
