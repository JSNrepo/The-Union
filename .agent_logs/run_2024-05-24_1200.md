### What you discovered
- The main chat area displayed generic "Loading..." text and a confusing "No messages yet" empty state when a user had not selected a workspace (or when no workspaces existed yet).
- The send button was correctly disabled when no workspace was selected, but it lacked any visual or semantic feedback explaining *why* it was disabled, which could be frustrating for accessibility and general UX.

### What you fixed/added
- Replaced the generic `messages.length === 0` empty state with a conditional that specifically handles the `!activeWorkspace` case, displaying a clear "No workspace selected" message with instructions to choose one from the sidebar.
- Updated the fallback header text from "Loading..." to "Select a Workspace".
- Added a dynamic `title` attribute (tooltip) to the Send Message button to explain why it is disabled ("Select a workspace to send messages" or "Type a message to send").
- Removed local execution logs (frontend.log, backend.log) to maintain repository hygiene.
