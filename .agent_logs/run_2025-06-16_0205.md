**What you discovered:**
I found an unhandled error in `frontend/src/app/page.tsx` when interacting with the Clipboard API. The frontend used `navigator.clipboard.writeText(msg).catch(...)` to handle copy failures, but unconditionally called `setCopied(true)` right after the API call, without waiting for the Promise to resolve. If clipboard permissions are denied, the `catch` handler runs, but the UI still briefly flashes a "copied" success state.

**What you fixed/added:**
I restructured the Promise logic in `handleCopy` inside `frontend/src/app/page.tsx`. Now, `setCopied(true)` and the success timeout are chained to the `.then()` block, ensuring that the success state is only displayed if the `navigator.clipboard.writeText` API returns a resolved promise. Rejections are properly caught and logged as before, but without triggering misleading UI states.
