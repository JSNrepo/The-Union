# Bolt Execution Log - 2024-06-04

## What I discovered
I found that the `MessageInput` component in `frontend/src/app/page.tsx` was attaching a global `document.addEventListener("keydown", ...)` inside a `useEffect` hook to handle pressing the Escape key to blur the input element. Using a global document listener for interactions specific to a single, focused element is an anti-pattern in React. It bypasses React's highly optimized Synthetic Event delegation system and can cause performance issues or unnecessary effect churn, particularly as the app scales.

## What I fixed/added
- Refactored the `MessageInput` component to remove the 'Escape' key handling from the global document listener.
- Handled the 'Escape' key blur logic using React's built-in `onKeyDown` synthetic event directly on the `<Input>` element.
- Appended this architectural learning to the `.jules/bolt.md` journal to ensure future optimizations leverage synthetic events for element-specific handlers.

## Next Recommended Target
Review other components (like modals or dropdowns) to ensure they are also using React's synthetic events (`onKeyDown`) for their escape/close logic rather than attaching global document listeners, unless the key command needs to be intercepted globally regardless of focus (like the `/` command to focus chat).
