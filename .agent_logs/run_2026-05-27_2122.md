What you discovered:
In the Chrome Extension `background.js` token synchronization script, `syncToken` used the `fetch` API to push authentication tokens to the backend without validating the HTTP response status. The `fetch` API only rejects promises on network failures, not on HTTP error statuses (like 403 Forbidden or 500 Internal Server Error). As a result, when the sync failed due to validation or server errors, the extension falsely proceeded to parse the response as JSON (which might cause a crash if HTML was returned) or incorrectly logged a success message.

What you fixed/added:
Added a `!response.ok` check immediately after the `fetch` call in `extension/background.js`. If the response is not ok (i.e. not a 2xx status), it throws a descriptive `Error` including the HTTP status, which is correctly caught by the existing try-catch block to prevent unhandled promise rejections and false success logs.

Add return type hints for Python nested asynchronous functions in `backend/app/main.py` (e.g. `fetch_agent_infos()` and `fetch_agent_data()`) to improve Pyright/MyPy strict type-checking coverage and prevent subtle bugs.
