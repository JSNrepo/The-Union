What you discovered.
The codebase is generally well-typed, achieving a high degree of coverage using Pyright. However, during the scout phase, I discovered that the `seed` function located in `backend/seed.py` was missing its return type hint (`def seed():`).

What you fixed/added.
I added the `-> None` return type hint to the `seed` function in `backend/seed.py` (`def seed() -> None:`). This seemingly minor change ensures consistency across the backend and satisfies Pyright's strict type checking requirements without breaking any existing execution flows.

Next Recommended Target
I recommend investigating if there are other areas lacking explicit typing or if some endpoint returns lack strongly-typed models (e.g. `list[dict[str, Any]]` could potentially be refactored into Pydantic models). Additionally, the use of `uuid.UUID` and strings interchangeably throughout the models might need standardization.
