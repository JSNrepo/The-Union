What you discovered:
I discovered that `frontend/src/app/page.tsx` was explicitly typing API responses as `any` which suppresses TypeScript's checks and goes against the project's preference for type safety. In the `fetchData` function, `wsData` and `agentData` were cast as `any` and then blindly checked for array type, which throws ESLint warnings for explicit any.

What you fixed/added:
I removed the explicit `any` casts for `wsData` and `agentData` and replaced them with `unknown`. I then updated the `Array.isArray()` conditionals to safely type-cast the result as `Workspace[]` and `Agent[]` respectively, ensuring that type safety is preserved. This fixes the ESLint errors while maintaining proper typing for downstream use of the responses.
